# Feedback camera

Work #324, reported in [in-game feedback](feedback-game/2026-10-07_105012/text.md). Opening feedback used to set pause before the screenshot, making third person yield to the overview camera. The feedback lifecycle now holds the rendered third-person lens and room enclosure before pausing, releases mouse capture, and releases that hold on close. Ordinary pause, menus and authored cameras retain their existing policy. A resize or place/settings change cancels the hold so normal fitting can run; the already captured image remains unchanged.

The native check is `game3d/tools/feedback-camera-check.mjs`. It uses an isolated browser, public-only routing and a stubbed GET capability response. It never sends feedback. The baseline reproduces the camera jump. Final round4 covers nine openings: F8, HUD button and a controlled prepaused state, each in desktop third person, desktop overview and phone overview. The third-person case enters room 203 and checks a visible enclosure. Opening-event and paused camera position, quaternion, field of view, player location and enclosure flags match exactly. Closing normal feedback resumes play without recapturing the mouse; closing an already-paused diagnostic leaves it paused.

The controlled pause cases set the pause state directly because capture mode disables the real pause menu. They do not establish actual menu/background-tab behavior. The unchanged screenshot compositor can omit the minimap and render an arrow differently; this patch fixes the world-camera reset, not those HUD discrepancies. Third-person framing in these captures is diagnostic evidence, not room-art approval.

All 85 images across baseline and four attempts are retained in `game3d/shots/feedback-camera/` and Showcase `feedback-camera-20261007`. Round1 stopped on overview easing between an early sample and the opening event; round2 passes six openings; round3 retained a harness failure from trying to open the disabled pause menu. Round4 uses the event-time snapshot and explicit prepaused setup. Original PNGs and lossless WebP copies are retained.

Full day-one magic routes pass desktop 74s and phone 72s, with no error overrides. Performance warnings against older baselines remain. CPU 645 tests and all repository checks pass after qualifying browser globals in the new harness. Independent source review found no blockers and inspected all 36 final images plus the four baseline images; it passes camera retention and panel layout only. No feedback POST or whole-scene art approval is claimed.
