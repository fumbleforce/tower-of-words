# Source-of-truth audit

2026-09-29, Codex. Proposal for [Review](../bible/#review/source-of-truth-audit); no source files have been changed. Inspected the working tree around commit `9e426c8` at 10:14 CEST. Other agents are editing it, so line numbers describe this inspection, not a frozen release.

The largest source of drift is that the bible reads several hand-written summaries live. A fresh fetch of an old summary still gives an old fact. The clearest example is its Places page: `bible/app.js:382` reads the Office section of FORMAT.md, which still says “Third floor” and lists removed characters. The played office is B2.

Use the game data for what is implemented, GUIDE for what Jørgen requires, and the original decision record for whether an asset is approved. These answer different questions. A model loading in the game is evidence of use, not approval. A draft describes a proposal, not implemented behavior. Keep these distinctions visible in the bible.

The tables identify one home for each fact family and a specific action for its copies. “Generate” means a derived view with a source link and build/source revision; it must not become another hand-maintained specification. “Delete” below means delete the duplicated passage after approval, retaining any unique rationale and decision history.
