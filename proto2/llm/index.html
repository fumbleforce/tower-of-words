Local LLMs as Emi

Five open models running locally on the RTX 3080 (10 GB) plus system RAM through llama.cpp. Each played Emi, the laid-back team lead, in casual Japanese at an N5 to N4 level, replying as strict JSON (line, kana, English, mood, and a correction note when the player makes a mistake). Six scripted player turns test a natural reply, over-polite keigo, a wrong particle, mixed English, a flirty line and an off-topic question. A second prompt asks for a small daily request from Goro using given words.

Recommendation

Orion 26B-A4B v1.1 (TheDrummer's roleplay tune of Gemma 4 26B-A4B) for desktop conversations. It kept Emi's voice, wrote the most natural casual Japanese, and every correction was right. Gemma 4 26B-A4B is the fallback: slightly plainer, fastest. Both only use about 4B parameters per word, so most of the model sits in system RAM and replies still take 2 to 3 seconds. In the game I would also constrain the output to the JSON schema (llama.cpp supports that), which makes broken JSON impossible.

Run it: LD_LIBRARY_PATH=~/ai/llama/bin ~/ai/llama/bin/llama-server -m ~/ai/llm-models/TheDrummer_Orion-26B-A4B-v1.1-Q4_K_M.gguf --fit on -c 8192 -fa on --jinja --port 8190 (an OpenAI-compatible API on port 8190). Image generation and the LLM share the GPU, so free ComfyUI's memory first.
