# Scene editor

Local page: `http://127.0.0.1:8771/tools/subplots/web/` (start the project server with `./start`). Image history and generation use the image generator on port 8772 (`tools/imagegen/run.sh`). No agent session is needed. The design and the stage plan are in [notes/tools/scene-editor.md](../../notes/tools/scene-editor.md).

The page lists public game scenes and private scenes together, each labelled (Public game or Private · Adult) with the file it lives in. A scene opens as a timeline of beats: lines and narration are edited in place, the speaker comes from a picker fed by the bible, beats move by dragging the handle or with Alt+↑ ↓, and pictures show where they play. Selecting a picture opens the Picture tab, where a render from the image generator's history replaces it; the pick goes live on Save. Undo and redo cover every edit since the scene was opened, unsaved edits are kept as a server draft, and every save keeps the previous version under Scene, Revisions. The timeline is one reading path: at a choice the author picks an option and the part it leads to (`go` or `call` to another node of the same file) follows below, read as its own scene and saved on its own; `if` branches show the side the path takes (`web/paths.js`). Preview plays the same path in the game's dialogue style; Play in game opens the private viewer (`?scene=`, with `mc=` and `flags=` from the path's switches) or the scene's place. Code: `web/app.js` (list, open, save, keys), `web/timeline.js`, `web/paths.js`, `web/inspector.js`, `web/pictures.js`, `web/preview.js`, `web/model.js` (what a step is), `web/store.js` (state, undo). Long Preview text scrolls from its first line without moving the picture or portrait. Back, Next, Edit and Close stay visible; Next waits for a choice. The composer (`web/images.js`) is Codex's and opens from the Picture tab. On narrow screens, the scene list, story and picture details stack vertically and scroll with the page.

A picture beat added in the editor is `{shot: {}, newPicture: true, imageSlot: 'new:…'}` (`model.js` newStep), offered where the recipe can show a picture (`capabilities.picture` from `pictureHelper` in recipes.mjs: `shot` or `pic` with a `PICS` table). The composer and the versions treat its slot like any other. On save the local provider promotes the render picked for it and gives the beat its file; recipes.mjs writes `shot("<file>", {})`, or `pic("<scene>.<n>")` with a new `PICS` entry (the file, the beat's narration or a placeholder as the caption, and the scene's first picture's `level` and `who`).

A public save runs every `game3d/tools/*story-check.mjs` before and after writing (`story_check` in api.py); a finding that is new undoes the write and answers 422 with `problems` (`node: what`), which `web/checks.js` puts on the beats in plain words. A save that passes rewrites the voice manifest (`voice-manifest.mjs`) and returns `unvoiced`, the lines its `--check` finds with no clip.

Saves are minimal, public and private: `encode.mjs` cuts a sequence into its beats with the comments and spacing around each (`listItems`, `writeList`) and pairs the edited beats with the originals (`alignSteps`). An unchanged beat keeps its exact text wherever it moved, an edited public step is written property by property, an edited recipe call changes only the arguments that changed (`encodeArray` in recipes.mjs, nested sequences and branches the same way), and new beats are written in the files' style. `test/roundtrip.test.mjs` saves every public node and every configured private sequence unchanged and expects the exact source back.

## Adapters

The public adapter (`source.mjs`) finds `nodes` objects in story modules without executing them. Cast, places, flags, events, words and deliveries come from the same public sources as the world bible (`authoring.mjs`). Existing helper expressions stay in the adapter, outside the editing interface. Ways in edit the story's `on` routes while keeping other nodes' routes and their priority (`routes.mjs`): only the entries that name the scene and changed are rewritten, an edited entry keeps its other properties in their order, and every other trigger keeps its exact text and comments. Routing that cannot be read statically is not rewritten.

Unsaved edits are posted as a draft (`draft`, or `draft` with `discard: true` to drop it). Save checks the whole source file's revision before replacing the selected node and changed routes, keeps the previous scene in Revisions, and commits nothing. Restoring a revision puts it in the editor, and Save makes it the scene again. Notes, compositions and picked pictures for public scenes are kept in the repository's administrative directory, outside exports. The catalog with `scope=all` returns public and local scenes together. Every row and read carries `audience` (`public` or `private`) and `where` (its file).

Local scene providers own their source format, generated outputs, revisions and image application. `SUBPLOTS_PROVIDER` is a JSON command array. Requests are JSON on stdin, responses JSON on stdout. `SUBPLOTS_PUBLIC_ONLY=1` disables this adapter for QA. The editor never discovers or opens user-owned folders.

Provider operations:

- `catalog`: `{scenes:[{id,provider,title,node,group,count}],errors:[]}`. IDs must have a provider prefix other than `public:`.
- `read`, with `id`: `{id,title,node,group,revision,steps,raw,entries,routesEditable,metadata,history,draft}`. Steps use the game's story step objects. `null` steps are preserved as a computed sequence. Entries are `{event,condition,once}`. Metadata contains notes, composition controls and a selected image `{id,url,file,seed,positive}`.
- `draft`, `validate`, `save`: receive that editable shape. Save must reject stale revisions and return the updated read shape. A provider must update its source of truth and regenerate derived files, rather than writing generated files alone. For local scenes, keep all data within the existing local content layout.
- `history`, with `id` and `version`: return an earlier read shape. Restoring it is an edit, not an immediate source write.

`GET /api/subplots/map` is the story map's public half (`storymap.mjs`, cached until a story file changes): every node with its day and place (from its file: `game3d/story/<place>.js` is day 1, `day<N>/` day N, `ongoing/` day 6 on, `conversations/` and `investigations/` any day; `placeholder/` is left off), its ways in (`on` and `start`) and its routes out (choices, jumps, calls, `next`, trips). The private half is each catalog row's `placement` (`place`, `day`, `condition`, from the recipe's `place`, `day` and `show`). `web/storymap.js` sorts both into days and places, `web/outline.js` draws the list, `web/restrictions.js` reads a condition into parts (day, time of day, first time only, who plays, private mode, Skimpy, needs), says them in words and writes a changed part back without touching the others, `web/placement.js` draws the sentence and its pickers in the Scene tab, and `web/board.js` draws the map board; a card dropped on a time, place or day becomes an edit of that scene (`moveScene` in app.js), and the open scene's unsaved placement is shown in the list and on the board (`liveItems`).

`POST /api/subplots/create` makes a public scene from a template (`web/templates.js`, written by `create.mjs`): `{day, place, template, title, event, who, name}`. The scene and its parts are added at the end of the place's `nodes` (`game3d/story/<place>.js` on day 1, `day<N>/` on days 2 to 5, `ongoing/` later) and its way in to `on` through routes.mjs, as `{ node, once: true }` ahead of the trigger's other entries when the trigger is in use. The story checks run before and after the write like a save, and a new finding undoes it (422 with `problems`). A file whose `nodes` or `on` is built in code is refused.

A placed public scene is checked in a normal run with `node tools/subplots/placement-reach.mjs <scene id> [--not <period>] [--phone]` (PORT and BASE pick the server and game folder): the game starts from the save it makes when that day begins (`days.js`), with the clock at the way in's time of day and the player at its place, continues from the title, walks up to the `talk:` target, taps its marker (and its Story row when a person opens the Talk menu), and passes when the scene's first step runs (a way in with no time of day is tried at each time until its target is there); `--not` checks that another time of day doesn't start it. It covers days 2 to 5 and `talk:` ways in. Private scenes have their own normal-run check (island/private/rewards/tools/normal-reach-browser.mjs). A private scene's first time only is `!<scene id>_seen` in its condition; a changed day also sets the recipe's `day`.

`GET /api/subplots/pictures?id=` returns the image generator's runs that belong to a scene (`scene_runs` in api.py): made in the composer for it, picked for it, from the round folder a live picture of it was copied from (the local provider's `pictures` operation finds the identical file under the rewards area), or from a round named after the scene or its pictures. Outside private mode (`/private`, tools/review_server.py) the API reads and writes public scenes only: a request naming a private scene (read, draft, save, comments, pictures) is refused, and the status and comment lists keep their public rows. Comments on beats: `GET comments?ids=`, `POST comment` (`add`, `reply`, `done`, `reopen`), kept by `comments.mjs`, which is also the command line for answering them (`node tools/subplots/comments.mjs open | reply <id> "<text>" | done <id>`). `GET status` gives every scene's standing (`scene_status` in api.py; the local provider's `status` operation for private scenes). The image service is proxied through a fixed localhost endpoint. Generation happens only when the user presses Generate. The existing service owns the GPU queue, model validation, generated files and render history. No generation job runs in the test suite.

Verification: `node --test tools/subplots/test/*.test.mjs`, `python3 -m unittest discover -s tools/subplots/test -p 'test_*.py'`, `GL=soft node tools/subplots/test/browser.mjs` (the editor at 2560 and 1366 on fixture data: labels, inline edits, undo and redo, speaker picker, drag, add, save, preview, revisions, a private picture pick) and `GL=soft node tools/subplots/test/images-browser.mjs` (the composer). Browser tests use fixture data and `SUBPLOTS_PUBLIC_ONLY=1`. A browser test stops at once when its port already has a server (one an earlier run left behind would serve another checkout's files); `SUBPLOTS_TEST_PORT` picks another port. They never open the real private library or start a render.

The bundled local adapter reads the existing scene-generator recipes. Run `python3 tools/subplots/setup_local.py` once to connect those sources. It preserves helper calls and alternate-language variants, edits existing place/day/availability fields, rebuilds the derived scenes, and applies selected renders to their picture slots. Fixed opening hooks remain in their existing position. Shot helpers expose supported framing and timing controls; other computed directions are preserved. For a changed line, stale local voice clips are retired; the editor does not generate speech. Public dialogue edits remove an outdated explicit voice reference and retain other staging fields.

Local saves back up source, derived outputs, metadata and the asset registry before rebuilding. A failed rebuild restores those files. Revision restoration includes picture-table references. Crash-recovery copies live alongside each scene's history in the configured state directory, under `recovery/<timestamp>/`; `files.json` maps the numbered backups to their original paths. Keep that directory when moving the project. Do not run an external recipe generator while saving from the editor.

Recipe lines keep English and Japanese side by side, and both are edited in the timeline. Public lines keep `text` (what the game shows) and `en`, the subtitle under Japanese (game3d/story/FORMAT.md).

Each shot opens the image composer with its own settings. The People frame edits clothing and appearance for that shot through `composition.people[id]` (`clothing`, `appearance`, `clothingNegative`, `appearanceNegative`). Missing keys inherit presets, while empty strings intentionally omit their words. Appearance replaces the full template block and its group short form. The shared-template editor remains a separate, explicitly labelled action. The same resolver feeds the preview, generation, face correction and recipe command. The composer uses the image generator's versioned character, outfit, scene, camera, framing, style, model and negative presets, portrait references, face correction, queue and render history. Existing renders can be selected for individual shots; multiple selections save together. Unrendered pictures are marked explicitly. An exact referenced archive file may provide a preview when its live file is absent; viewing it does not promote it.

`GET /api/subplots/authoring` supplies the public authoring vocabulary through static parsing, cached until its source files change. Tests never request user-owned files or submit real generation jobs. The dedicated image composer browser fixture is `GL=soft node tools/subplots/test/images-browser.mjs`.

Configured `checks` run after rebuilding and before accepting a save. A failed check restores source and derived outputs from the same backup as a failed rebuild. New local configurations include the existing language-visibility and encounter-entry checks.


Recipes: `node tools/subplots/compose.mjs <recipe.json> [--count N --seed S --dry-run --wait --out DIR --owner NAME --end-session]` renders a composition (the composer's own JSON) through the image generator's queue.  `--wait` downloads private renders too (the same local private cookie `/private` sets, sent only to a local dashboard on a machine that has island/private/), fails loudly instead of saving an error body, and saves each picture as webp in the round folder (the one above `recipes/`, or `--out`). The master PNG on the image generator is not changed. `--owner NAME` says who made the renders (else `IMAGEGEN_OWNER`, else `agent`), and every request also names its round. `--end-session` cancels only this run's jobs and ends the session only when nothing else is queued or running. It uses `assembleComposition` from `web/image-compose.js`, so the editor and the command share one prompt builder, and the job stores `compose`, so the editor opens the picture with every block filled. Mature and Adult pictures always carry the soft-scene negative unless the recipe says `hard`. `start` (`{image, denoise, mask}`, a repo-relative picture) makes it img2img, or an inpaint with a mask; `loras`, `control` (an LLLite guide) and `huefix` run in the same queue (art/PROMPTS.md, How a picture is made). `details` is a free note, stored and shown. For older pictures the composer's "Fill from prompt" (`web/image-guess.js`) guesses blocks from the prompt without changing the record.

The agent recipe command calls `prepareAgentGeneration(recipe, presets, name)` in `agent-recipe.mjs` for every recipe before queueing. This reusable function validates the shared typed `COMPOSITION_SCHEMA` contract in `web/image-compose.js`, then calls its normalizer, defaults and assembler; it does not build prompts separately. It reads the dashboard’s current versioned presets; `--presets FILE` is for `--dry-run` fixtures only. It refuses whole-prompt overrides, rewritten style/exclusion/camera/framing blocks, character exclusion switches and manual appearance/clothing words. Select character/outfit and exclusion presets by id; their configured words remain intact. Exclusion words are manual per section (`sectionNegatives`, keys in `web/image-section-negatives.js`), per person (`clothingNegative`, `appearanceNegative`, added after the template's and outfit's words) and in the older free `negative`; they only add to the exclusions. Scene direction, staging, extra scene words, pose/place/light text and supported queue settings still use the normal assembler. A scene attachment must provide both the full scene editor `subplotId` and its exact `imageSlot` (read them from the editor; structural validation does not look up scene or slot existence); standalone recipes omit both. Browser editing controls are unchanged.

Reward pictures call `prepareRewardGeneration(recipe, presets, name)`, a strict wrapper around that same function and assembler. An Adult-mode reward (`hard: true`, independent of content rating) gets the default negative preset selection resolved by the composer’s existing `applyDefaults` and nothing more. A nonadult reward (`hard` false or left out, CLAUDE.md "Reward tiers by mode") gets that selection plus the negative preset marked soft (“On for every nonadult reward”), whether or not the recipe names it, and is refused when no such preset is configured. A recipe may add negative presets and exclusion words; leaving out a default preset is refused. The CLI chooses this wrapper automatically for recipe paths in `island/private/rewards/`, including resolved symlinks. Use `--reward` for reward recipes kept elsewhere. The wrapper marks the composition `reward: true`, and the shared assembler keeps the default presets and, when nonadult, the soft preset on for any such composition, whatever is typed, in the browser composers too (`lockedExclusions` in `web/image-compose.js`; the composer shows them on and locked, notes/tools/scene-editor.md).

Agents must use this composer queue, not custom Comfy runners, raw generation requests or pasted image repairs (GUIDE, Art). The command rejects bypass fields automatically; it does not sandbox arbitrary Python or HTTP calls outside the command. No second image pipeline or agent override switch is provided. Run `node --test tools/subplots/test/agent-recipe.test.mjs tools/subplots/test/compose.test.mjs` for refusal, preset preservation and queue integration checks.

A shot's picture opens in the composer filled in: `GET picture-source?id=&slot=` (`picture_source` in api.py) finds the render picked for the shot, else the image generator's record of the round file the live picture is a byte copy of (`picture_copies` in local.py; the latest render of that name in that round), else the round's prompts file. Its blocks fill the composer when it has them, Fill from prompt when not, and the original prompt, negative and settings always show under Original prompt, editable and used as they stand until a block changes. "Small changes to this picture" starts from the shot's picture (img2img, strength 0.35) with the same seed. Through the editor's proxy, private mode passes on to the image service as the same cookie.

A shot's versions (`web/versions.js`) need no open composer: New version and Repaint a part take the shot's settings from the composer's `shotJob` (its composition, filled from `picture-source` the first time; nothing is queued for a picture with no record unless it is a repaint), set a new seed, and mark the job's `compose` with the scene, the shot (`imageSlot`) and `made` (`new-version` or `repaint`, with `repaintText`). A repaint is `start: {image, denoise, mask}` from the picture the beat shows, the image gen queue's inpaint. A shot is known by its picture, not its place (`imageSlots` in recipes.mjs): `pic:<PICS key>` or `file:<file>`, with `#2` for a picture shown twice. When a pick or a new picture beat changes a shot's picture, the local provider keeps the id it had in `slots.json` beside the scene's metadata (`ids`), so adding, moving and deleting beats and picking a new picture all leave a shot's id, picks, compositions and versions where they were. Shots used to be `image:N` by place; the first read of a scene freezes what each of those meant (`legacy`), renames its saved picks, compositions and draft, and the `pictures` endpoint names renders made under an old id by the shot's id now (`as_shot_ids` in api.py). A shot's versions are the renders whose `compose` names the scene and shot, the picked render, the render `picture-source` found, and renders started from the shot's picture, with the queue's jobs laid over them. Compare is `#compareDialog`. Associated rejected attempts remain in the shot’s Versions and Compare with their rejection label and reason. Deleted renders stay hidden. The general image picker still omits rejected renders.

Direct the shot and Place and light (layout in notes/tools/scene-editor.md, Composer) are `web/image-direct.js`. The staging is the composition's `stage` (`{people: {<character id>: {x, d, placed, facing, toward, gaze, lookAt, expression, height}}, contact, lightFrom, mood}`). `web/image-stage.js` turns it into prompt words for `assembleComposition` (so a `compose.mjs` recipe takes a `stage` too), sorts camera blocks into the Shot, Angle and Lens rows by their `group` and `diagram` fields (older blocks by their id), and works out the geometry that `web/stage-view.js` draws as SVG (the stage and the tile diagrams). Example pictures on the tiles come from the image gen history's `preset` filter (`web/block-examples.js`). Make examples queues a 512 px render of a stand-in figure for each block without one, marked `compose.example`. Preview this place (`placeJob`) queues the shot's setting in its light with no people, marked `compose.placePreview` (`place:<setting>|<light>`); a finished one is picked up from the queue's jobs (`noteDone`) or, after a reload, from the history. The composer's library leaves both out. `promptParts` in `web/image-compose.js` cuts the built prompt into the stretches each block wrote, from the same build as `assembleComposition`, for the tinted Generated prompt.

The composer has the dashboard's own tools: every block picker has "+ New…" and Edit (`web/block-editor.js`; kinds and fields from `tools/imagegen/web/blocks.js`), the library rates, deletes, restores from Trash, filters by who made a picture and opens a lightbox with compare and the prompt diff (`web/library.js`, markup and keys from `tools/imagegen/web/gallery.js`, the same module the dashboard page uses), and Picture tools carry a start picture with a painted mask, LoRAs, an LLLite guide picture and colour fixes to the queue (`web/image-tools.js`).

Prompt block text overrides live at `composition.blockOverrides[kind][presetId][field]`. Supported fields are `text` for location, light, pose and negative blocks, `prompt` for camera and framing blocks, and `quality`, `anchors`, `suffix`, `negative` for style. A missing field inherits the template; an empty string deliberately omits its words. `image-block-words.js` resolves these for the shared assembler and exposes the shot forms. Local overrides are carried by generated `compose` metadata and restored from history, including background-only shots. Place-preview keys include effective local words and shape, and adapted previews do not become shared block examples.

The composer’s mode buttons change only `composition.hard`. They preserve exact copied prompt overrides and use the existing standing-soft-exclusion rule. The assembled negative shown in Exclude is the same string sent by Generate.

The picture library sorts individual pictures newest first, including batch members and live jobs. The editor requests `pictures=1`, so each history envelope contains one picture. Older pages use `before`, `before_n` and `before_run` together, preserving the timestamp, permanent picture number and run tie-breaker across page boundaries.

A place preview key is `place:<setting>|<light>|<hash>`. The hash covers the effective setting and light words, style and framing, custom shape and exclusion words. Legacy template names retain their local text overrides while the key uses the canonical preset ids.
